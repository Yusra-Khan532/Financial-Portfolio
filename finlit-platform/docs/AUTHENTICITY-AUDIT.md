# Authenticity and compliance audit

Date: 2026-10-20. Scope: frontend (pages, content, components, demo data), index.html / sitemap / robots / manifest, site-api (emails, chat prompt, seed), backend mail templates, scheduler claims.
Method: read the shipped copy and compared every factual claim with the code, `deploy/scheduler.sh`, `backend/finlit/auth` and the docs.

Overall: the site is already more careful than most (it states plainly that FinLit is not SEBI/AMFI registered, demo companies are labelled "Sample"/SMP-, the testimonial is a single named quote, no fake logos, awards, user counts or AUM). The remaining risk is concentrated in a few places: performance results, unprovable "checked / live / fast" claims, a security line that reads as untrue, and credential wording next to an unregistered-entity disclaimer.

Severity: H = fix before launch (regulatory or demonstrably untrue); M = unverifiable or misleading, soften or evidence; L = tone / polish.
Status: FIXED = edited by this audit (files owned). Everything else is a proposal for the owning agent.
